What happens before the answer

CloudQueryX makes the hidden chatbot memory layer visible.

Most assistants answer from a prompt you cannot inspect. This demo shows every step: what gets stored, what gets recalled, why it was selected, and what context reached the LLM.

01 User message "Remember my project and explain it later."
02 Store memory, source, entity, relationship, event
03 Retrieve pgvector + full text + graph + freshness
04 Rank semantic match, importance, recency, evidence
05 Context bundle token-budgeted evidence sent to the LLM
06 Answer + learn LLM answers; CloudQueryX stores useful new context

Without CloudQueryX

LLM-only apps guess or forget.

The prompt has to carry everything. Memory is hidden in app code, retrieval is hard to explain, and stale context can slip into answers.

With CloudQueryX

The model gets a clean context bundle.

CloudQueryX retrieves memories, source chunks, graph relationships, and events, then ranks and trims them before the LLM call.

What recruiters see

Not just chat. Real backend behavior.

The playground exposes scoring, token budget, freshness, memory writes, and a trace view that explains every answer.

Why It Matters

Without a context runtime, teams wire memory together by hand. CloudQueryX makes context retrieval a product surface instead of hidden glue code.

Typical AI app

Application code stitches together a vector DB, SQL tables, custom memory rows, graph lookup, ranking, and prompt formatting before every LLM call.

  • Context logic scattered across app code
  • Hard to explain why a fact was selected
  • Token budget handled late in the prompt

With CloudQueryX

Your app asks CloudQueryX for a context bundle. CloudQueryX retrieves, ranks, explains, trims, and formats the context in one place.

  • One context runtime before the model call
  • Every item includes scores and reasons
  • Context is selected before handoff

2. RetrieveMemory, source chunks, graph, events, full text, and pgvector candidates are collected.
3. RankRelevance, text match, freshness, importance, and mode boost determine priority.
4. BudgetUseful context stays full, medium context is trimmed, low signal is excluded.
5. HandoffCloudQueryX formats the context bundle; the LLM generates the final answer.
